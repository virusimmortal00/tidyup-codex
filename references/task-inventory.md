# Complete Codex task inventory

The desktop `list_threads` tool is a sidebar view capped at 50 ordinary tasks in the version checked on 2026-09-23. It has no cursor. This cap does **not** apply to the documented Codex App Server [`thread/list`](https://learn.chatgpt.com/docs/app-server), which returns an opaque `nextCursor`. Prefer that API for paginated, read-only discovery before planning cleanup, then verify coverage.

## App Server inventory

On each accessible Codex host, use its own App Server connection. The installed `codex` CLI can start one with `codex app-server` (JSONL over stdio); follow the documented `initialize` request and `initialized` notification handshake. Inspect `codex app-server --help` and, if needed, generate the version-matched protocol schema with `codex app-server generate-json-schema --out <temporary-directory>`. `codex agents` and `codex resume --all` are interactive browsers, not machine-readable complete inventories. `codex archive <SESSION_ID>` can archive a known local session but does not replace project-aware review.

Call `thread/list` with `archived: false`, an appropriate page `limit`, and no cursor for the first page. Pass each returned `nextCursor` until it is null. Supply **all relevant** `sourceKinds` explicitly: when omitted or empty, the documented default includes only `cli` and `vscode`, which can miss app-created tasks. The current schema accepts `cli`, `vscode`, `exec`, `appServer`, `subAgent`, `subAgentReview`, `subAgentCompact`, `subAgentThreadSpawn`, `subAgentOther`, and `unknown`. Omit `isPinned` so both pinned and ordinary tasks are included. Inspect the current schema for changed values or filters. Do not use `searchTerm` or a single `cwd` as proof of complete project coverage: titles are incidental, and linked worktrees use different paths. Match returned IDs against the exact saved project, canonical repository paths, worktrees, host, and Git origin; use app `read_thread` or App Server `thread/read` to resolve uncertain ownership and outcomes. Deduplicate by ID.

Cross-check visible sidebar and pinned IDs against the paginated results. On a local host, also compare IDs with read-only local state as described below, and inspect any extra in-scope IDs by `thread/read` or `read_thread`. In one check on 2026-09-23, all 39 visible local Codex IDs appeared in `thread/list`, but its state-database-only pages returned 489 IDs while the local database had 584 unarchived rows; some omitted IDs were readable with `thread/read`. The default scan-and-repair mode returned fewer IDs still. Thus a null `nextCursor` proves only the end of that filtered listing, not a complete host inventory. Reconcile differences before declaring coverage complete, and record remaining gaps in the audit file. If archived history is needed for a specific decision, use `archived: true` and page it separately. Use the app's `set_thread_archived` for selected app tasks when available; the local CLI's `codex archive <SESSION_ID>` or App Server `thread/archive` can handle known local sessions where app tools cannot. Archive by ID, not ambiguous title, and verify the result. App Server archiving also attempts to archive spawned descendants, so inspect their status first.

## Last-resort local state check

For local cross-checking, or if App Server inventory is inaccessible, the host may have internal `~/.codex/state_5.sqlite` and `.codex-global-state.json` files. On one host inspected on 2026-09-23, the SQLite `threads` table exposed IDs beyond both the sidebar and App Server listings; global state contained `thread-project-assignments`. These are observed internal files, **not** a stable public API. Inspect the current schema and read SQLite with `mode=ro`; never write to these files. Avoid dumping unrelated task text or credentials.

Cross-check all visible and pinned local IDs and archive flags, then confirm extra candidates via `read_thread` or `thread/read`. Build project candidates from exact saved-project assignments, canonical repository paths, linked worktrees, and Git origin metadata; a shared title or branch name alone is insufficient. Reconcile other available indexes; `session_index.jsonl` was incomplete on the inspected host. A local database does not enumerate another host. If schema, project mapping, host coverage, or completeness remains uncertain, mark the inventory incomplete and use the skill's conservative sidebar batch fallback.
